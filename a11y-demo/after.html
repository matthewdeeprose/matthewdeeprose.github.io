How a screen-reader user experiences this

  • The Full name box is announced with its label, so you know exactly what to type.
  • The help control is a real button with a clear name — reachable by keyboard and announced as “Help: how we use your email address, button”.
  • The campus options are announced inside a group called “Preferred campus”, so you always know what you are choosing.
  • Required fields still show a “*” for sighted users, but the requirement is conveyed natively, so a screen reader announces each as “required” — and the “*” itself is hidden from the reader, so there is no “asterisk” noise.
  • If you miss a required field or mistype your email, submission is blocked and focus moves to the first field that needs attention — its label, “invalid” state and error message are announced together, so you fix it in place.
  • The Register button is a real button — reachable and operable with the keyboard, and announced as a button.
  • The page declares its language, so a screen reader uses the right voice.
