Badge size, style and border

Colour does not change how big the badge is. Three things do: the letter height, the padding below, and how long the word is.

Style

Filled puts a block of colour behind the word. Outlined draws a ring, and the word takes the status colour on the page. That changes two things: how much of the panel is strong colour, and the test the colour has to pass. An outlined badge is text, so it takes the test text takes.

Saturated area

How much of the panel is strong colour. A contrast score cannot see this at all. We report it. We do not judge it. Neither the guidance nor WCAG sets a limit here, so there is nothing to pass or fail.

What must you be able to read as you walk up?

Everything on this panel must be readable from 600 mm away. That is the floor, and it is not the decision. The decision is what must also be readable from about 1,400 mm, because only one or two things can be that big. Pick one, and whatever held that job before steps down.

Limit on how strong a status colour can be

When the page picks colours for you, it picks the ones that look most different from each other. Those are usually the strongest colours in the palette. Cap height is the height of a capital letter. It is what you would measure with a ruler held against the glass. Font size is bigger than that, because it leaves room above and below for accents and for letters that hang down.

Verification

A colour-blindness view drawn with the wrong numbers still looks believable. So we work the same colours out twice, once with our own arithmetic and once with the browser's, and compare. The checks then test the sizes against sums done by hand, test the colour chooser both ways round, and compare what the page actually draws against what the model says it should.

What the accessibility check cannot see

Two tools check this page for accessibility problems every time we change it. Both read the page as it arrives. A tab that is not the one showing is hidden, and a hidden tab is invisible to them, so they check the first tab and nothing else.

That is not a small gap. When we moved four sections to the Detail tab, the number of things the tools asked us to check by hand fell from 119 to 34. Nothing got better. The tools simply stopped looking.

So we run them twice. Once on the page as you get it, which is the test we have to pass. Then again with every tab and every drop-down forced open, which is the test that tells us what the first one missed. Both runs are written up in the same report, and neither is allowed to stand for the other.
